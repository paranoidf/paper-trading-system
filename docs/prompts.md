# 代表性 AI Prompt 记录

以下记录选取本次实现中最能体现问题拆解、约束表达和人工复核的 4 个 Prompt。原始需求文档只作为产品/工程要求处理。

## 1. 先规格、再计划、后代码

**场景：** 空仓库中需要交付完整全栈应用，需求同时包含认证、行情、撮合、实时通信和文档。

**Prompt：** “先完整读取需求，建立 capability map；列出歧义、保守假设、非目标、可测试成功标准、技术栈和命令。在规格完成前不要写产品代码；随后把纵向切片计划写入 `tasks/plan.md` 与 `tasks/todo.md`。”

**我想解决的问题：** 防止 AI 直接堆代码、漏掉交付物或擅自扩大范围。

**AI 结果与人工调整：** 形成五个稳定模块，并明确成交价、初始持仓、冻结规则、重连恢复和 GitHub 外部操作边界。我检查依赖方向无环且每项必选功能有验收条件后才允许进入实现。

## 2. 用不变量驱动撮合引擎

**场景：** 撮合与结算是最容易“看起来能跑、账却不平”的部分。

**Prompt：** “先写会失败的纯单元测试，覆盖跨价位价格优先、同价 FIFO、部分成交、挂单价成交、买方价格改善、资金/持仓冻结和拒单原子性；金额使用整数分。RED 成立前不要实现。”

**我想解决的问题：** 让测试表达业务规则，不测试框架调用次数，并及早验证最高风险逻辑。

**AI 结果与人工调整：** 5 个核心测试先因模块缺失而失败，最小实现后全部通过。我额外核对部分成交案例的现金守恒，并让身份模块只通过显式 `TradingAccount` 边界暴露结算字段。

## 3. 把实时隔离当成安全合同

**场景：** WebSocket 很容易广播方便，却把一个用户的账户数据发给另一个用户。

**Prompt：** “为两个真实 WebSocket 客户端写集成测试：无效 token 必须以 1008 关闭；行情可广播；Alice 下单后的 `account.updated` 只能到 Alice，不能到 Bob。若测试超时，保存原始失败并定位竞态和资源清理。”

**我想解决的问题：** 用外部可观察结果证明鉴权与隐私隔离，同时防止测试留下 open handle。

**AI 结果与人工调整：** 初次运行暴露首帧监听竞态和 teardown 超时。我没有增加任意 sleep 掩盖问题，而是把首帧监听前置并显式关闭 socket/WSS；完整集成套件随后通过。

## 4. 对浏览器输入保持不信任

**场景：** 前端收到的 WebSocket JSON 即使顶层类型正确，内部数组元素也可能畸形。

**Prompt：** “新增一个先失败的测试，把 `account.updated.positions` 设为 `[{}]`；要求客户端忽略它。随后对行情、账户、持仓、委托、成交做运行时结构校验，并验证重连先拉快照、停止后不再重连。”

**我想解决的问题：** 避免 TypeScript 类型断言把不可信网络数据伪装成安全对象。

**AI 结果与人工调整：** 浅校验测试按预期失败（账户回调多调用一次）；逐项守卫修复后回到 GREEN。人工复核确认没有使用 `any` 或静默默认值绕过边界。
